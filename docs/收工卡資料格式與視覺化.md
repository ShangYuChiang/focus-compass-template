# 收工卡資料格式與視覺化框架

## 建議結論

日常分析以 **CSV** 為主、**JSON** 作完整結構化備份、**Markdown** 作閱讀與知識管理版本。三種格式用途不同，因此系統預設一次全部匯出；桌面版只需選擇一次資料夾。

| 格式 | 最適合用途 | 建議工具 |
|---|---|---|
| CSV | 統計、篩選、樞紐分析、趨勢圖 | Excel、Power BI、Tableau、Python pandas |
| JSON | 完整備份、程式串接、資料庫匯入 | Python、JavaScript、SQLite、API |
| Markdown | 人工閱讀、週／月回顧、知識庫 | Obsidian、Notion、GitHub |

## CSV：一日一列的事實表

每一列代表一天，欄位固定且使用可長期相容的英文名稱：

| 欄位 | 類型 | 說明 |
|---|---|---|
| `date` | YYYY-MM-DD | 工作日日期，作為主要時間索引 |
| `completed_count` | integer | 當日完成任務數 |
| `focused_seconds` | integer | 原始專注秒數，避免四捨五入損失 |
| `focused_minutes` | decimal | 方便試算表直接作圖的分鐘數 |
| `overtime_count` | integer | 有超時的工作段數 |
| `mvp_task_id` | string | MVP 任務識別碼 |
| `mvp_title` | string | 產卡當下的 MVP 名稱快照 |
| `plot_twist` | string | 當日主要劇情轉折 |
| `tomorrow_axis_id` | enum | `career`／`research`／`teaching`／`investing` |
| `tomorrow_axis` | string | 主軸中文名稱 |
| `gratitude` | text | 感謝日記 |
| `created_at` | ISO 8601 | 首次產卡時間 |
| `updated_at` | ISO 8601 | 最後編輯時間 |

CSV 使用 UTF-8 BOM，Windows Excel 可直接開啟繁體中文。文字欄位都使用雙引號包覆，內容中的逗號、換行與雙引號不會破壞表格。

## JSON：有版本的完整交換格式

最外層包含：

- `schemaVersion`：格式版本，未來欄位調整時仍能辨識。
- `type`：固定為 `bubu-daily-review-export`。
- `exportedAt`：匯出時間。
- `cardCount`：卡片數量。
- `cards`：收工卡陣列。

每張卡片分為四個區塊：

- `metrics`：完成數、專注秒數／分鐘數、超時段數。
- `mvp`：任務 ID 與名稱快照。
- `reflection`：劇情轉折與感謝日記。
- `nextDay`：明日主軸 ID 與名稱。

## 建議的視覺化順序

1. 每日專注分鐘折線圖，加上 7 日移動平均。
2. 每週完成任務數長條圖。
3. 每週超時工作段比例，用來觀察任務是否經常低估。
4. 明日種子主軸分布圖，檢查四個主軸是否長期失衡。
5. 日曆熱圖，以每日 `focused_minutes` 呈現行動連續性。
6. 感謝日記關鍵詞頻率；文字屬私人反思，不建議直接以正負情緒分數評價自己。

## 建議的資料夾結構

```text
步步資料/
├─ raw/                 # 每月保留一份 JSON 原始匯出
├─ analysis/            # CSV 分析資料
├─ reports/             # Excel、Power BI 或圖片報表
└─ journal/             # Markdown 閱讀版
```

建議每月底匯出一次「全選 JSON」作完整快照，再匯出「當月 CSV」製作圖表；需要閱讀與分享時才產生 Markdown。
